# RAVEN 纯内存历史回收实施与验收方案

普通 Falco 的共享插件和签名 enclave 使用同一份 RAVEN 检测器。回收对象限于当前会话内存。运行时的证据存储、索引和回收过程都使用 RAM。测试输入、输出和验证记录由测试程序单独管理。

## 回收约定

1. 默认历史窗口为 600 秒。以单调递增的事件时间水位为准，严格早于边界的旁证可以回收，边界上的事件保留。现场空闲时钟也推进回收。迟到事件不能使覆盖起点倒退。
2. 两端采用相同的字节计费和稳定的淘汰顺序。RAVEN 常驻状态的高水位为 128 MiB，低水位为 96 MiB。下一次计费将越过上限时，优先收回最老的可释放历史。图、边上的每个证据 ID、索引、进程关系、账本、规则链、去重和待结算告警都纳入预算。预算与操作系统 RSS、enclave 分配器统计分开验证。
3. 逐事件删除旁证。持续访问的文件也会释放旧 ID。回收空边、孤立节点、无依赖的退出进程及其索引。保护未完成规则链的直接事件、活跃后代仍依赖的最小祖先关系、正在发送的快照。保留原版命中时的成员和标量，以及原版在更新或回放结束时刷新的字段。发生截断后给出有效起点和原因。
4. 受保护状态耗尽预算时，记录受影响的输入序号和原因，结束该段关联并继续采集。正常负载要求强制分段次数为零。历史回收、输入丢失、输出丢失分别计数。

**去重边界。** 普通 Falco 和 enclave 都按「规则名、匹配的事件 ID 集合」去重。去重键跟随完成匹配的那条事件保留。时间窗口或内存预算回收该事件时，也释放对应的键。之后重投相同的原始记录可以再次告警。默认配置下，同一敏感文件访问在事件时间推进 10 秒后重投，原版和两端都只报一次。推进 601 秒后重投，原版仍报一次，两端各报两次。预算压力可能使去重覆盖短于 600 秒。原版在整个会话中保留去重键。

## 执行顺序

先实现共享回收逻辑和边界用例，然后在独立 QEMU 快照中构建共享插件、普通 Falco 宿主及签名 SGX Simulation enclave。先完成原版对照，再执行百万条测量。使用与前次相同的固定源码版本、原始输入和规则。将实际结果、命令、输入及构建指纹单独归档。

| 检查 | 通过条件 |
|---|---|
| 原版回归 | 原批次及 34 组回归通过。两份归档的 10 万条输入在能容纳整批的验证预算下，与原版的全部有序告警逐字段一致，只归一化已有的随机 ID 和规则路径。 |
| 强制回收 | 两端在同一小预算下核对边界、迟到、热文件、祖先依赖及 PID 复用。独立期望值核对保留/删除的 ID、顺序、覆盖边界、过载诊断及恢复。 |
| 持续负载 | 重复访问同一文件、持续产生新进程与新路径各连续 1,000,000 条。每个运行方式和负载组合各用一个实例，全程保持状态。每万条及回收后记录实占内存、计费、覆盖起点、回收原因和输入输出计数。 |
| 稳定性 | 每组至少三个回收周期。预热后最后 50 万条的同阶段实际内存基线最大差值 ≤8 MiB。常驻计费 ≤128 MiB，enclave 全程可信堆高水位目标 ≤384 MiB。报告最大告警及追溯时长的范围。 |
| 丢失 | 用有序输入序号及独立预期告警核对交付。真实采集核对驱动丢失、ring 丢弃、格式拒绝、消费游标和输出。正常负载要求零丢失、零强制分段、零历史落盘。 |

超过既有文件回放单份 64 MiB 的输入须分批进入同一引擎实例。测试报告注明采用的输入路径和实测计数口径。遇到影响要求的取舍时向用户确认，并在本文记录决定。

用户选定增加两组真实采集长测。分别在临时目录反复写同一文件、持续创建短命子进程与独立文件，每组送入 RAVEN 至少 100 万条归一化事件。enclave 直接消费内核 ring，普通 Falco 重放对应的同批现场记录。四组逐序号的确定性百万条测试另行执行。

## 测量口径与复现

确定性输入沿用原基准的事件生成规则，事件时间相隔 1 毫秒。检测器逐条核对输入 ID 是否等于当前序号，并累计有序摘要。测试端独立核对每条命中的直接事件、图边的证据 ID 和次序、全部有序 Falco 告警及最大整行字节数。旧输入的完整证据对照使用 1 GiB 验证计费上限，百万条测量使用默认的 128 MiB。

普通 Falco 采样整个进程的 RSS。enclave 采样可信分配器的当前值及历史高水位，并单列宿主进程峰值。追溯时间以事件时间计算，报告完整覆盖窗口的长度和受保护证据能达到的最早时间。已处理并回收的事件记在 `evicted`，超预算中断关联的事件另记在 `skipped`。按预算在同一时间戳内回收时，`after_sequence` 记录淘汰边界对应的输入序号。按时间到期时，保留恰好落在 600 秒边界上的记录。

真实同文件负载写入 1,000,000 次，每 10,000 次打开读取一次。新进程负载依次创建 250,000 个子进程，每个子进程创建和写入独立文件，每 2,500 个子进程有一次标记读取。测试端核对工作负载发起的操作、现场输入、采集计数、目标告警及普通 Falco 对同一批输入的结果。读取计数日志控制生产进度，实测速率由客体执行时间决定。
