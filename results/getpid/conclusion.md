# 最小通信闭环验收

本次已在用户提供 ISO 安装的 **QEMU TCG + Ubuntu 22.04.5 + Intel SGX SDK SIM** 中完成真实 eBPF → SGX Simulation 通信闭环。没有 MOAT，也没有内核认证桥。

## 真实内核通道

低速运行：每轮 10,003 次显式 `syscall(SYS_getpid)`，请求间隔 1,000 μs。所有加载探针的模式均满足 attempted = submitted = processed = matched = 10,003，reserve_failed = format_rejected = 0。

| 模式 | 处理数 | 数据 ECALL | SDK 数据输入字节 | Host 整批复制字节 |
|---|---:|---:|---:|---:|
| M0 无探针发生器 | 不适用 | 0 | 0 | 0 |
| M1 普通用户态 | 10,003 | 0 | 0 | 0 |
| M2 逐事件 ECALL | 10,003 | 10,003 | 2,560,768 | 0 |
| M3 批量 ECALL | 10,003 | 6,218 | 101,925,456 | 2,560,768 |
| M4 常驻直接消费 | 10,003 | **1** | 0 | **0** |

M4 在 enclave 中复制的事件载荷为 2,560,768 B，即每条 256 B 一次边界复制。消费位置和生产位置均为 2,640,792，超过 1 MiB 环容量并正确排空。M4 总 ECALL 为 3（配置、登记、数据运行各一次），OCALL 为 0。有限直接消费模式也处理了同样的 10,003 条事件。

M3 为固定容量封送，低速时受 100 μs 封批目标影响，平均每批约 1.61 条，但 SDK 仍复制完整批对象。这里记录实际复制量和调用量，不据此推断硬件 SGX 性能。

## 持续运行与边界

- 60 秒常驻测试：24,880 条目标调用全部提交和处理，无预留失败、无格式拒绝、无重复消费；1 次数据 ECALL、0 次 OCALL。消费和生产位置均为 6,568,320，累计多次环绕，载荷复制 6,369,280 B。停止后排空时间约 0.441 ms，仅是该次 TCG/SIM 运行观察值。
- 满环恢复：暂停消费者 3 秒，发生器不限速调用 20,000 次；submitted = 3,971，reserve_failed = 16,029。恢复后全部 3,971 条已提交事件被处理并排空，未覆盖未消费记录。
- SIM enclave 内的独立测试通过：空队列、连续双映射环尾跨界、BUSY 等待与恢复、DISCARD、异常长度、异常索引、描述符溢出和重叠、错误版本、重复序号、相同轨迹回放、尾批以及停止排空。
- 对照 CSV 脚本另以每模式 3 条、1 次重复完成调用链检查，见 `compare-script-check.csv`。主要原始数据在 `runs.csv`，对应 JSON 和 `smoke.log` 原样保留。
- 工作区核心源码与实际客体构建源码 SHA-256 一致，见 `source-sha256.txt`。

## 结论与范围

真实内核 ring buffer → 模拟 enclave 直接读取 → 内部副本处理 → 回写消费者位置的软件流程已验证；常驻模式整轮只需要一次数据 ECALL。构建与运行命令见 [构建说明](../../poc/README.md)，已有磁盘可用 [QEMU 脚本](../../vm/Start-VM.ps1) 启动。

客体已正常关机，最终磁盘结构检查通过。启动后在 `/home/poc/poc` 可直接运行已构建程序，或使用构建脚本重新编译。

格式合法的匿名测试事件会被接受，说明来源认证尚未实现。SIM 不证明硬件隔离或硬件转换成本。本次是最小功能验收，尚未进行多发生器、复制后并发修改外部载荷、恶意取消映射、各配置五次完整负载对照，以及硬件 SGX 验收。`compare.py` 已提供五次对照的复现入口。
