# RAVEN 完整证据的内存与告警大小

本页记录引入自动回收之前的完整历史实现。文末的采样补丁以该版源码为基线。[现行纯内存回收方案](../../../poc/falco/RAVEN-历史回收.md)

2026-11-21。两种负载各回放 100,000 条事件，各产生 10 条告警。普通 Falco 和签名 enclave 的 20 条检测结果都与固定版本的原版 RAVEN 逐字段一致。

这个规模可以继续采用方案 1，在内存中保留完整证据。若要让固定 512 MiB 堆的 enclave 长期处理持续出现的新进程和路径，建议引入可按需完整回读的旧证据存储，并释放相应的内存图记录。该负载在后 50,000 条仍平均增长 **22.95 MiB/万条**，到 100,000 条时堆高水位已达 **266.45 MiB**，与上限相差 **245.55 MiB**。两种合成负载的告警频率均为每万条一次，其他告警频率、事件组合和路径长度会改变这些数值。当前没有部署速率或运行时长目标，容量判断以事件数为单位。

每格增长量先在同一进程内相减，再取三次独立运行的中位数。普通 Falco 使用进程 RSS，enclave 使用可信堆当前已分配字节数。基线取自输入装载完成、第一条事件处理前，终点取自第 100,000 条事件处理后、回放结束刷新前。1 MiB 等于 1,048,576 字节。

全程进程峰值取自无探针发布版本的 GNU time，覆盖启动、检测、证据刷新和输出。enclave 另用 Open Enclave 分配器读取可信堆历史高水位，含分配器保留空间，覆盖最后一次告警输出。SGX Simulation 宿主进程在输入处理期间的 RSS 净增中位数两种负载都是 0 MiB，内部堆的增长由独立探针测得。硬件 SGX 的 EPC 驻留量需要在硬件上测量。

### 两种负载分别消耗了什么

**同一文件。** 一个 PID 执行一次程序，此后对同一合成路径写入 99,989 次、打开读取 10 次。每一万条中的倒数第二条读取触发一次 `sensitive_access_chain`。图最终只有 5 个节点和 5 条边，但边上累计 100,002 项事件 ID 引用。每次命中都留下一份告警快照。回放结束时，同一条边的最新证据又会反映到先前的告警。第 100,000 条处理完时可信堆已用约 63.41 MiB，结束刷新后约 90.87 MiB，完成序列化和输出后测得的历史高水位为 156.25 MiB。单独回放前 10,000 条时最大整行是 424,484 字节，到 100,000 条时为 4,474,496 字节。

**新进程和新路径。** 每四条为一组，包含进程启动、两次文件操作、进程退出。每组使用不同的 PID 和不同的文件路径，每一万条有一次读取命中规则。100,000 条产生 25,000 个进程和 25,000 条路径，图含 50,003 个节点、100,010 条边和 125,000 项事件 ID 引用。近期事件账本已停在 2,048 个 PID，进程树仍有 25,000 个 PID。末段增长主要对应累计的进程、节点和边。每次命中只牵涉自己的进程与文件，整行告警最大为 8,210 字节。[证据图](../../../poc/falco/plugin/graph.cpp) · [进程树、事件账本与告警快照](../../../poc/falco/plugin/raven.cpp)

告警大小取实际写出的完整 Falco JSONL 的 UTF-8 字节数，扣除换行。当前配置在 `output`、`message` 和 `output_fields.rz.result` 中携带检测记录。表中最后一列单独计算解码后的 `rz.result`。对重复访问，即使旧证据以后移到磁盘，只要仍输出当前格式的完整证据，组装和发送单条大告警的开销仍要预留。

## 签名 enclave 的实时采集补测

单独运行 Modern eBPF 现场入口，每种负载一次，ring 为 32 MiB。重复访问组通过 `pwrite` 对一个新建的临时文件写 20,000 次，每 10,000 次重新打开读取一次。新进程组依次 fork 5,000 个子进程，每个子进程创建并写入一个新文件，其中两个子进程重新打开自己的文件。两组的临时目录都位于快照内的 `/root/`，以触发原版已有的敏感文件读取规则。

| 现场负载 | 实际送入 RAVEN 的事件 | 第 1 万条可信堆增量（MiB） | 第 2 万条可信堆增量（MiB） | 可信堆高水位（MiB） | 进程 RSS 峰值（MiB） | 最大完整告警（字节） |
|---|---:|---:|---:|---:|---:|---:|
| 反复写同一文件 | 20,076 | 1.78 | 2.82 | 15.82 | 883.95 | 886,906 |
| 持续 fork 并创建新路径 | 20,535 | 26.70 | 10.97 | 42.07 | 882.70 | 8,350 |

两组均排空 ring，驱动丢失、报文丢失、ring 丢弃和格式拒绝均为零。现场分母含客体内同时出现的其他 RAVEN 事件。前一组的两条目标告警分别保留 10,001 和 20,001 条修改证据（含创建），完整告警分别为 436,861 和 886,906 字节。后一组的两条目标告警各保留一条访问和两条修改证据。脚本核验了图边上事件 ID 的数量、唯一性和顺序，并将最后一次读取的 ID 与触发告警的事件核对。现场在命中时发送证据快照，文件回放会在结束时刷新旧告警的证据。两种负载的进程事件构成也不同，容量比较应使用同一入口的一组数据。[现场工作负载与核验](../../../poc/falco/bench/raven-memory-live.py)

## 复现同批回放

环境是 Ubuntu 22.04 x86_64、Linux 5.15.0-198-generic、4 vCPU、6 GiB 的独立 QEMU 快照，使用普通 Falco 0.45.2、Falco libs 0.26.1 和签名的 Open Enclave SGX Simulation。发布版本的 Falco 可执行文件、共享插件、enclave 宿主和签名映像四项 SHA-256 均与先前的原版对照记录一致。[先前的构建指纹](upstream-parity-fixed.json)

输入采用一行一条的 RAVEN 事件，事件 ID 连续，合成时间间隔为 1 毫秒。两个模式共享完全相同的输入字节及一份空 PCAP。普通 Falco 通过 `raven_zeek` 事件源运行，enclave 通过 `falco-sgx --plugin` 入口运行。单独取前 10,000 条做预试验，再以新进程执行 100,000 条主试验。每组主试验先跑一次发布版本，然后以相同配置独立采样三次。每次都核验 10 条告警的触发事件、图边的完整事件 ID 列表及顺序、整条输出的字节数和归一化摘要。

原版对照使用相同输入和 UTC 时区，逐字段比较所有检测记录，只归一化随机告警 ID 与规则安装路径。原始证据 ID 全程参与比较。两份 100,000 条输入可由[生成步骤](../../../poc/falco/RAVEN-历史回收.md)重建。原始测量 JSON 另含各输入和文件的 SHA-256、所有采样时点、三次运行的独立读数与每条告警大小。[原始测量 JSON](memory-benchmark.json) · [同批回放脚本](../../../poc/falco/bench/raven-memory.py)

在一次性源码副本中先保存常规构建的 `lib/libraven_zeek.so`、`bin/falco-sgx` 和 `falco-enclave.signed` 至发布目录，保留这三个相对路径。再从 `falco/` 应用 `patch -p1 < bench/raven-memory.patch`，重建 `raven_zeek`、`falco-sgx`、`sign-falco` 三个目标，将它们放入另一个采样目录。基线目录取自已有的官方 syscall 回放，包含 `reference.scap`、`libcontainer.so` 和 `falco_rules.yaml`。原版使用项目固定的 RAVEN 提交 `3b5fbf5f33e2d1287d3ff0f546023106f787a92e` 及其 full 检测器。[项目构建步骤](../../../poc/falco/README.md) · [采样补丁](../../../poc/falco/bench/raven-memory.patch) · [分配器与 RSS 探针](../../../poc/falco/bench/raven_memory_probe.hpp)

在项目的 `poc/` 目录运行，以下变量分别指定普通 Falco 软件包、两套构建、基线目录、新建的输出目录和固定版本 RAVEN 源码。

```bash
python3 -B falco/bench/raven-memory.py "$PACKAGE" "$RELEASE" "$PROFILE" "$BASELINE" "$NEW_RUN" \
  --events 100000 --repeats 3 --upstream "$RAVEN_SOURCE"
```

现场补测在同一个采样源码副本中继续应用 `bench/raven-memory-live.patch`，重建 `sign-falco` 和 `falco-live`。每种负载使用独立空目录，分别命名为 `repeat` 和 `churn`，将 `live.yaml`、`falco_rules.yaml` 和 `raven_zeek_rules.yaml` 按配置中的名称链接到该目录，再从该目录运行下列命令。[现场采样补丁](../../../poc/falco/bench/raven-memory-live.patch)

```bash
sudo env TZ=UTC FALCO_HOSTNAME=raven-memory-live /usr/bin/time -q -f %M -o maxrss.kib \
  "$LIVE_BUILD/falco-live" "$LIVE_ENCLAVE" live.yaml 32768 - \
  falco_rules.yaml raven_zeek_rules.yaml -- python3 -B "$BENCH/raven-memory-live.py" "$CASE" \
  > alerts.jsonl 2> process.log
python3 -B "$BENCH/raven-memory-live.py" --summarize "$PWD"
```
