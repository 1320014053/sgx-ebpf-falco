# 阿里云 ecs.c7t.xlarge 硬件 SGX 性能复测计划

这一批在 4 vCPU 的 `ecs.c7t.xlarge` 上复测 Falco 实时采集的吞吐、业务开销、告警延迟、空闲开销、内存和回放成本。凡是使用 enclave 的实验都在真实 Intel SGX 硬件上运行，enclave 报告 `ATTRIBUTES.DEBUG=0`。这一批与 [c7t.large 批次](../aliyun-c7t-large/README.md) 分开存放，旧批次的数据只作定性参考，因为机器、源码和事件订阅都已改变。

计划建档于 2026-11-25。这一批不做告警一致性对比（RQ1），只回答跨边界方式（RQ2）和代价（RQ3）。

## 为什么要复测

| 自上一批以来的改动 | 影响的数据 |
| --- | --- |
| 单个 `falco_live` ECALL 忙等，改为采集、分析、检测三个常驻线程（`bdf44fb`） | 吞吐、CPU、丢失 |
| 订阅全部系统调用，改为按 Falco 0.45.2 规则选择 72 个，启用 RAVEN 时补订 8 个（`989c277`） | HTTP 开销。上一批 SGX 每个请求约 15 条记录，原生 Falco 约 5.2 条 |
| 告警按 64 KiB 刷新，改为逐条交付；ring 读空时由忙等改为 500 µs 到 30 ms 的退避睡眠 | 告警延迟、空闲 CPU |
| RAVEN 复核改为增量跟踪 | RAVEN 内存 |
| RAVEN 和 Zeek 可分别启用（`df41ac2`） | 新增单检测器配置 |
| 机器由 2 vCPU 升级为 4 vCPU | 所有对照组都要在新机器上重测 |

GETPID 前期实验的代码自上一批以来没有改动，这一批不重测。

## 测试规则

- 每个测试点只运行 1 次。计时测试的负载持续 30 秒，不另设预热，统计覆盖这 30 秒。
- 每秒采样一次驱动计数、各线程 CPU 和整机 CPU。报告单次运行的结果，并附运行内每秒的最小值、中位数和最大值，用来判断这次运行是否稳定。
- 只在以下情况补测该点一次：`errors` 不为 0，配置核对不符，相邻档位结果不单调，或每秒采样出现与负载无关的尖峰。补测保留原记录，另起轮次编号。
- 所有 SGX 运行使用同一提交和同一份 DEBUG=0 签名镜像，单个 8 MiB ring 由 4 个 CPU 共用，正式运行关闭轨迹录制，不绑核。原生 Falco 使用 `cpus_for_each_buffer: 0` 和 `buf_size_preset: 4`，与 SGX 的 ring 对齐。
- CPU 换算为单个 CPU 的百分比，4 个 CPU 全部占满记为 400%。

## 有效性检查

开始测量前读一次运行中 enclave 的 REPORT，确认 `DEBUG=0`，MRENCLAVE 和 MRSIGNER 与签名产物一致，并记录 CPU 拓扑、EPC 容量、内核版本和 PKS 位。每个配置先运行一次短冒烟，确认能启动、能产生告警、计数正常。

每次 SGX 运行结束后自动核对以下各项，任一不符则该次运行作废：

- `event_selection` 的订阅数：S1、S3 及其变体为 72，S2、S4 为 80。
- 统计行 `detectors` 与配置一致。
- `errors` 各项为 0，`format_rejected` 为 0，`trace_bytes` 为 0。
- 停止后生产位置与消费位置相等。

## 配置

| 编号 | 配置 |
| --- | --- |
| B0 | 无监控 |
| N1 | 原生 Falco 0.45.2，官方规则 |
| S1 | SGX，官方规则，默认 `idle: sleep`、`buffered_outputs: false` |
| S2 | SGX + RAVEN，`init_config: {raven: true, zeek: false}` |
| S3 | SGX + Zeek，`init_config: {raven: false, zeek: true}` |
| S4 | SGX + RAVEN + Zeek，`init_config: {raven: true, zeek: true}` |
| S1-spin | S1，改为 `idle: spin` |
| S1-buf | S1，改为 `buffered_outputs: true` |

S2 至 S4 都包含官方规则。S2、S3 相对 S1 的差值分别是 RAVEN 和 Zeek 的代价。RAVEN 和 Zeek 共用一个检测线程，所以要单独检查 S4 的代价是否超过两者之和。原生插件只支持回放，原生 Falco 不能现场运行 RAVEN 或 Zeek，检测器的原生对照只在回放实验中进行。

## 负载

| 负载 | 做法 | 主要压力 |
| --- | --- | --- |
| L1 系统调用 | `falco-load` 按固定速率打开并关闭 `/dev/null` | 官方规则和 RAVEN。每次 `openat` 产生一条 RAVEN 文件访问输入 |
| L2 报文 | `tcp-load` 按固定速率在回环上建立 TCP 短连接，连接同一端口，收发 64 字节后关闭 | Zeek。连接中的 `connect`、`write` 等调用也进入 RAVEN |
| L3 HTTP | 两条本机持久连接，1 KiB 响应，持续请求 | 混合负载 |
| L4 标记 | 约 20 请求/秒的 HTTP 背景流量，每 0.05 秒执行一次标记命令，30 秒约 600 个 | 告警延迟 |

吞吐分别报告系统调用记录/秒、RAVEN 输入/秒和报文/秒。L2 只连接一个正常端口，不应触发扫描告警，避免告警输出混入吞吐测量。

## 实验

| 编号 | 回答的问题 | 配置 | 负载与档位 | 时长 |
| --- | --- | --- | --- | --- |
| E1 系统调用吞吐 | 最高零丢失速率，能否达到 10 万条/秒 | N1、S1–S4 | L1：首档 6,250 对/秒用于换算，再测 5 万、10 万、15 万、20 万条/秒和不限速，最后在临界区间二分至多 2 点。连续 2 档出现丢失后停止升档 | 每点 30 秒 |
| E2 报文吞吐 | Zeek 的报文处理上限 | S1–S4 | L2：1k、2k、4k、8k、16k 连接/秒和不限速，再二分至多 2 点 | 每点 30 秒 |
| E3 跨边界方式 | 退避睡眠与忙等的 CPU 和延迟取舍 | S1、S1-spin | L1 的 1 万、5 万、10 万条/秒，叠加每 0.1 秒一次标记 | 每点 30 秒 |
| E4 HTTP 开销 | 业务吞吐降幅 | B0、N1、S1–S4 | L3 | 30 秒 |
| E5 告警延迟 | 告警 p99 能否低于 2 ms | N1、S1–S4、S1-spin、S1-buf | L4 | 30 秒 |
| E6 空闲 CPU | 没有流量时的常驻开销 | N1、S1–S4、S1-spin | 无负载 | 30 秒 |
| E7 内存 | 可信堆是否有上限 | RAVEN、Zeek，各原生与 SGX | RAVEN 重复路径、新进程与新路径各 100 万条；Zeek 回放大量 TCP 会话的 PCAP | 按事件数 |
| E8 启动与回放 | 启动开销，以及上一批 30 万条时原生比 SGX 慢的原因 | 原生、SGX | 回放 60、3 万、10 万、30 万、60 万条；30 万条时原生另将输出导向 `/dev/null` 和文件各一次 | 按事件数 |

各实验记录的指标如下。

- **E1、E2**：送入量（实收加驱动丢失）、实收、驱动丢失、报文丢失、`ingest_stalls`、`peak_blocks`、排空时间、各线程 CPU。L1 下 S3 应接近 S1，关闭 Zeek 时报文记录应为 0，E2 中 raven_zeek 告警应为 0。
- **E3**：各线程 CPU、睡眠 OCALL 次数（sleep 模式下等于 `idle_polls`）、丢失、告警 p50/p95/p99。
- **E4**：请求/秒、相对本批 B0 的降幅、请求 p95/p99、采集进程 CPU、每个请求的系统调用记录数和报文数。S1 每个请求的记录数应接近 N1。
- **E5**：告警 p50/p95/p99（最近秩）、成功配对数和缺失数，标记与告警使用同一单调时钟。上一批原生 Falco 的 p99 为 28.8 ms，接近 libscap 的 30 ms 退避上限。SGX 现在默认使用同样的退避，S1 与 S1-spin 的差值用于回答 2 ms 目标需要付出多少 CPU。
- **E6**：采集进程和各线程 CPU、`idle_polls`。上一批 SGX 空闲时占满一个 CPU。
- **E7**：可信堆峰值、后半程同一回收阶段的堆变化范围、进程 RSS 峰值、回收次数、告警数。Zeek 另记超时回收后的可信堆。
- **E8**：总耗时、就绪前耗时、就绪后事件/秒、峰值 RSS、user/sys CPU、告警数，以及原生与 SGX 的规范化告警摘要是否相同。最大一档为 60 万条，因为 `falco-sgx` 只接受不超过 64 MiB 的未压缩 SCAP，100 万条约 94 MB。

## 预计用时

每次运行另有约 10 到 15 秒的固定开销，包括启动 enclave、等待 `capture_ready` 和排空。

| 阶段 | 约需 |
| --- | --- |
| 开机、传输产物、身份核验、各配置冒烟 | 1 至 1.5 小时 |
| E1，约 40 次运行 | 27 分钟 |
| E2，约 32 次运行 | 21 分钟 |
| E3 至 E6，25 次运行 | 17 分钟 |
| E7、E8 | 15 分钟 |
| 补测余量 | 15 分钟 |
| 合计 | 约 3 小时 |
